## 1. 개요 및 목적
- 인증된 사용자가 개인별로 할일(Todo)을 카테고리 단위로 관리하고, 시작일/종료일을 기준으로 진행 상태를 추적할 수 있는 웹앱.
- Category는 관리자(Admin)가 전역으로 등록·관리하며, 일반 사용자는 그 목록 중 하나를 선택해 Todo에 지정한다.
- 목적: 사용자별 데이터 격리(소유권 보장), 관리자 중심의 일관된 카테고리 체계, 기간 기반 할일 관리, 상태별 필터링을 통한 업무 가시성 제공.

## 2. 핵심 용어 정의 (Ubiquitous Language)
| 용어 | 정의 |
|---|---|
| User | 회원가입 및 로그인으로 인증된 앱 사용자. Role은 일반회원(Member) 또는 관리자(Admin) |
| Admin | Category와 회원 목록을 관리할 권한을 가진 User(Role = Admin) |
| Category | 할일을 분류하는 전역 단위. Admin이 등록·관리하며, 모든 사용자가 공통으로 선택해 사용. 미지정 시 '기본' 카테고리로 간주 |
| Todo | 사용자가 등록한 할일 항목. 시작일/종료일/메모를 가지며, 하루에 여러 건 등록 가능 |
| 상태(Status) | 할일의 진행 단계: 시작전 / 진행중 / 완료 / 지연 |
| 지연(Overdue) | 종료일이 지났으나 완료되지 않은 상태 |
| 소유권(Ownership) | Todo와 회원정보는 생성한 User에게만 귀속되며 본인만 접근·수정·삭제 가능. Category는 Admin만 등록·수정·삭제 가능(전역 소유) |

## 3. 핵심 엔티티와 속성

### User
- id, email(로그인 식별자), password(암호화), name, role(Member/Admin), createdAt
- 회원가입 후 로그인 가능, 로그인 사용자는 자신의 회원정보 수정 가능
- Admin은 회원 목록 조회 및 Category 등록·관리 권한을 가짐(회원정보 자체를 대신 수정하진 않음)

### Category
- id, name, isDefault(기본 카테고리 여부), createdBy(등록한 Admin의 userId), createdAt
- 사용자별로 존재하지 않고 전역(공용) 목록으로 존재. 등록·수정·삭제는 Admin만 가능
- 일반 사용자는 Admin이 등록한 Category 목록 중 하나를 선택해 Todo에 지정. 미지정 시 '기본' Category로 자동 지정

### Todo
- id, userId(소유자), categoryId(Admin이 정의한 Category 중 선택), title, memo, startDate, endDate, completed, createdAt, updatedAt
- status(시작전/진행중/완료/지연)는 별도 저장 필드가 아니라 completed 플래그와 오늘 날짜를 startDate/endDate와 비교해 매 조회 시 파생 계산한다(5장 참조)
- 한 사용자가 같은 날짜(구간)에 여러 개의 Todo를 등록하는 것을 허용(1일 1건 제약 없음)

## 4. 엔티티 관계
- Admin(User 중 role=Admin) (N) — (N) Category : Category는 특정 Admin 1명의 소유물이 아니라 Admin 그룹 전체가 공동 관리하는 전역 목록. createdBy는 등록자 기록일 뿐 소유 관계가 아니다.
- User (1) — (N) Todo : 사용자별 할일 소유
- Category (1) — (N) Todo : 하나의 Category를 여러 User의 여러 Todo가 공통으로 참조(선택)
- User와 Category는 소유 관계가 아니라 "선택/참조" 관계다. Todo는 정확히 하나의 User(소유)와 하나의 Category(참조)에 연결된다.

## 5. 할일 상태 및 전이 규칙
| 상태 | 조건 |
|---|---|
| 시작전 | 오늘 < startDate, 미완료 |
| 진행중 | startDate ≤ 오늘 ≤ endDate, 미완료 |
| 완료 | 사용자가 완료 처리(completed = true), endDate 경과 여부 무관 |
| 지연 | endDate < 오늘, 미완료 |

- 상태는 completed 플래그와 오늘 날짜 대비 startDate/endDate 비교로 매 조회 시 파생 계산(별도 상태 필드 저장 불필요).
- 완료 처리는 사용자가 명시적으로 토글(완료/미완료) → 완료 해제 시 날짜 기준으로 시작전/진행중/지연 중 재계산.

## 6. 핵심 비즈니스 규칙
1. 인증되지 않은 사용자는 앱 기능(할일 조회·등록·수정·삭제)에 접근할 수 없다.
2. Todo/회원정보에 대한 수정·삭제는 소유자 본인만 가능하다(소유권 검증 필수).
3. Category는 Admin만 등록·수정·삭제할 수 있다. 일반 사용자는 Category 목록을 조회·선택만 할 수 있다(생성·수정·삭제 불가).
4. Todo 등록 시 Category를 지정하지 않으면 전역 '기본' Category로 자동 지정한다.
5. 전역 '기본' Category는 1개만 존재한다. 삭제/수정 가능 여부는 요구사항에 명시되지 않아 범위 밖(미정).
6. 시작일은 종료일보다 늦을 수 없다(startDate ≤ endDate).
7. 한 사용자는 하루(또는 겹치는 기간)에 여러 개의 Todo를 등록할 수 있다(건수 제한 없음).
8. 할일 목록은 카테고리별, 상태별(시작전/진행중/완료/지연)로 필터링 가능해야 한다.
9. Admin은 전체 회원 목록을 조회할 수 있다. 단, 다른 회원의 Todo·회원정보를 직접 수정·삭제하는 권한은 요구사항에 명시되지 않아 범위 밖(미정).

## 7. 주요 유스케이스
### 일반 사용자(Member)
- 회원가입 / 로그인
- 회원정보 수정
- Admin이 등록한 Category 중 선택해 Todo 등록(시작일/종료일 캘린더 선택, 메모 입력, 하루 여러 건 가능)
- 할일 목록 조회 및 필터링(카테고리별 / 시작전 / 진행중 / 완료 / 지연)
- 할일 수정(편집 화면) / 삭제

### 관리자(Admin)
- 회원 목록 조회(회원관리)
- Category 등록 / 수정 / 삭제(카테고리 관리)

## 8. 예외/에러 케이스
| 케이스 | 처리 규칙 |
|---|---|
| 회원가입 시 이미 존재하는 이메일로 가입 시도 | 가입 거부, 중복 이메일 오류 반환 |
| 로그인 시 이메일/비밀번호 불일치 | 로그인 거부, 인증 실패 오류 반환(계정 존재 여부는 노출하지 않음) |
| 미인증 상태로 Todo/Category API 접근 | 접근 거부(401), 로그인 화면으로 유도 |
| Admin이 삭제하려는 Category를 참조 중인 Todo가 이미 존재 | Category 삭제 시 이를 참조하던 기존 Todo는 전역 '기본' Category로 자동 재할당한다 |
| 일반 사용자가 Category 등록/수정/삭제 API를 직접 호출 | 권한 없음(403) 처리 |
| Todo 등록/수정 시 startDate > endDate | 등록/수정 거부, 유효성 오류 반환(규칙 6 위반) |
| 소유자가 아닌 사용자가 타인의 Todo/회원정보 수정·삭제 시도 | 권한 없음(403) 처리(규칙 2 위반) |
