## 문서 개요
- 목적: PRD 3.1 MVP 범위 및 사용자/관리자 시나리오를 화면 단위로 구체화하여 프론트엔드(React 19 + TypeScript) 구현 기준을 제공한다.
- 표기: 텍스트 기반 ASCII 박스 레이아웃. 실제 스타일(색상/폰트 등) 미정의, 레이아웃 구조와 인터랙션 요소만 다룸.
- 반응형 원칙(PRD 6장): 데스크톱은 다단 레이아웃, 모바일(≤768px)은 1열 스택 레이아웃으로 전환. 접근성(a11y)은 PRD상 범위 제외로 본 문서에서 다루지 않는다.
- 공통 네비게이션: 로그인 후 상단에 "Todo 목록 / 회원정보수정 / (Admin만) 회원관리·카테고리관리 / 로그아웃" 메뉴 노출.

## 반응형 웹 UI 설계 원칙 (PRD 6장)
- 브레이크포인트: 데스크톱(>1024px) / 태블릿(768~1024px, 데스크톱 레이아웃을 기준으로 폭만 축소) / 모바일(<768px, 1열 스택).
- 상단 네비게이션: 데스크톱은 메뉴 전체 텍스트 노출, 모바일은 로고+햄버거(☰) 아이콘으로 축소하고 탭 시 메뉴가 드롭다운/슬라이드로 펼쳐진다.
- 목록형 화면(Todo목록/회원목록/카테고리관리)은 데스크톱 표(Table) → 모바일 카드(Card) 스택으로 전환(각 화면 절에 이미 명시).
- 폼 화면(회원가입/로그인/Todo등록·편집/회원정보수정)은 구조 변경 없이 카드 폭만 화면에 맞춰 축소, 버튼/입력 필드는 터치 조작을 고려해 최소 44px 높이 유지.
- 모바일 필터(Todo목록의 카테고리/상태 필터)는 가로 스크롤 칩 또는 아코디언으로 접어 화면 상단 공간을 절약한다.
- 별도 모바일 전용 앱/네이티브 컴포넌트는 없음(PRD 3.1) — 반응형 웹 하나로 전 기기 대응.
- 인증이 필요한 모든 화면(Todo목록/등록/편집, 회원정보수정, 관리자 화면)은 미인증 상태 접근 시 401을 받아 로그인 화면으로 리다이렉트된다(도메인 8장) — 각 화면 절에 개별 명시.

**네비게이션 축소/확장 예시 (모바일)**
```
[닫힘 상태]                      [☰ 탭 후 펼쳐짐]
+----------------------------+  +----------------------------+
| ☰ my-ToDoList              |  | ✕ my-ToDoList              |
+----------------------------+  +----------------------------+
                                 | Todo 목록                   |
                                 | 회원정보수정                 |
                                 | (Admin만) 회원관리           |
                                 | (Admin만) 카테고리관리        |
                                 | 로그아웃                     |
                                 +----------------------------+
```

## 화면 목록
1. 회원가입
2. 로그인
3. Todo 목록(필터 포함)
4. Todo 등록
5. Todo 편집
6. 회원정보 수정
7. 관리자 - 회원 목록
8. 관리자 - 카테고리 관리

## 1. 회원가입 화면

**목적/진입 경로**: 신규 사용자 계정 생성. 비로그인 상태에서 최초 진입 또는 로그인 화면의 "회원가입" 링크로 진입.

```
+--------------------------------------------------+
|                 my-ToDoList                       |
|                                                    |
|              [ 회원가입 ]                          |
|  이메일(id)  [_______________________]            |
|  비밀번호    [_______________________]            |
|  이름        [_______________________]            |
|                                                    |
|              [   가입하기   ]                      |
|                                                    |
|  이미 계정이 있으신가요? [로그인]                    |
+--------------------------------------------------+
```

**주요 인터랙션 요소**
- 이메일 입력 필드: 이메일 형식 클라이언트 검증 → 시나리오 1 Main Flow 2 ("이메일 형식 정규식 검증")
- 비밀번호/이름 입력 필드
- [가입하기] 버튼: 클릭 시 중복 이메일 확인 → 성공 시 로그인 화면 이동, 실패 시 인라인 오류 메시지("이미 사용 중인 이메일") 표시 → 시나리오 1 Alt Flow 3a, 도메인 8장
- [로그인] 링크: 로그인 화면 이동

**반응형**: 모바일/데스크톱 동일한 단일 카드 중앙 정렬 레이아웃(구조 차이 없음, 폭만 축소).

## 2. 로그인 화면

**목적/진입 경로**: 기존 사용자 인증. 비로그인 상태 진입 시 기본 랜딩 화면, 세션 만료(401) 시에도 이 화면으로 리다이렉트.

```
+--------------------------------------------------+
|                 my-ToDoList                       |
|                                                    |
|              [ 로그인 ]                            |
|  이메일(id)  [_______________________]            |
|  비밀번호    [_______________________]            |
|                                                    |
|              [   로그인   ]                        |
|                                                    |
|  [!] 이메일 또는 비밀번호가 일치하지 않습니다.        |  (오류 시에만 노출)
|                                                    |
|  계정이 없으신가요? [회원가입]                       |
+--------------------------------------------------+
```

**주요 인터랙션 요소**
- 이메일/비밀번호 입력 필드
- [로그인] 버튼: 인증 성공 시 Access/Refresh Token 발급 후 Todo 목록 화면으로 이동 → 시나리오 2
- 오류 메시지 영역: 인증 실패 시 "계정 존재 여부 비노출" 문구로 표시 → 시나리오 2 Alt Flow 2a, 도메인 8장
- [회원가입] 링크
- (비고) 401 응답으로 자동 재발급 실패 시(Refresh Token 만료) 이 화면으로 강제 이동 → 시나리오 3 Alt Flow 3a

**반응형**: 회원가입 화면과 동일 패턴(중앙 카드, 폭만 축소).

## 3. Todo 목록 화면 (필터 포함)

**목적/진입 경로**: 로그인 성공 후 기본 진입 화면(메인). 상단 네비게이션에서 "Todo 목록" 클릭 시에도 진입.

```
+--------------------------------------------------------------+
| my-ToDoList   [Todo목록] [회원정보수정] [로그아웃]              |
+--------------------------------------------------------------+
| 카테고리: [전체 ▾]   상태: [전체][시작전][진행중][완료][지연]   [+ Todo 등록] |
+--------------------------------------------------------------+
| [ ] 보고서 작성  업무   진행중  09/01~09/05  분기 보고서 초안  [편집][삭제] |
| [x] 장보기       개인   완료    08/20~08/20  (메모 없음)       [편집][삭제] |
| [ ] 세금 신고    기본   지연    08/01~08/10  국세청 홈택스     [편집][삭제] |
| ...                                                            |
+--------------------------------------------------------------+
|                    (조건에 맞는 항목 없음: "표시할 Todo가 없습니다") |
+--------------------------------------------------------------+
```

**주요 인터랙션 요소**
- 카테고리 필터 드롭다운(Admin이 등록한 전역 목록 표시): 시나리오 7 Main Flow 3, 도메인 6장 규칙8
- 상태 필터 버튼그룹(전체/시작전/진행중/완료/지연): 시나리오 7, 도메인 5장(파생 상태)
- [+ Todo 등록] 버튼 → Todo 등록 화면 이동 → 시나리오 6
- 목록 각 행: 체크박스(완료 토글) → 시나리오 10, 클릭 시 completed 반전 및 상태 즉시 재계산 표시
- 기간과 편집 버튼 사이에 메모 열 표시(메모 없으면 데스크톱 표는 '-', 모바일 카드는 해당 줄 생략)
- [편집] 버튼 → Todo 편집 화면 이동 → 시나리오 8
- [삭제] 버튼 → 확인 후 즉시 목록에서 제거 → 시나리오 9
- 빈 목록 안내 문구: 필터 결과 없음(오류 아님) → 시나리오 7 Alt Flow
- (비고) 미인증 상태로 접근 시 401 → 로그인 화면으로 리다이렉트 → 시나리오 7 Alt Flow 1a, 도메인 8장

**반응형**
- 데스크톱: 표 형태(한 행에 제목/카테고리/상태/기간/액션 가로 배치)
- 모바일: 각 Todo를 카드형으로 세로 스택, 필터는 상단에 접이식(아코디언) 또는 가로 스크롤 칩으로 배치, 상단 네비게이션은 햄버거 메뉴로 축소

**모바일(<768px) 레이아웃 예시**
```
+----------------------------+
| ☰ my-ToDoList              |
+----------------------------+
| [전체][시작전][진행중][완료] |  (가로 스크롤 칩)
| 카테고리: [전체 ▾]           |
| [+ Todo 등록]                |
+----------------------------+
| [ ] 보고서 작성              |
|     카테고리: 업무 · 진행중   |
|     09/01 ~ 09/05           |
|     분기 보고서 초안         |
|     [편집]        [삭제]    |
+----------------------------+
| [x] 장보기                   |
|     카테고리: 개인 · 완료     |
|     08/20 ~ 08/20           |
|     [편집]        [삭제]    |
+----------------------------+
```

## 4. Todo 등록 화면

**목적/진입 경로**: Todo 목록 화면의 [+ Todo 등록] 버튼 클릭 시 진입(모달 또는 별도 페이지).

```
+--------------------------------------------------+
|  Todo 등록                                   [X] |
+--------------------------------------------------+
|  제목      [_______________________________]     |
|  카테고리  [기본 ▾]  (Admin 등록 목록 중 선택)      |
|  시작일    [ 2026-08-26  📅 ]                     |
|  종료일    [ 2026-08-30  📅 ]                     |
|  메모      [_______________________________]     |
|            [_______________________________]     |
|                                                    |
|  [!] 시작일은 종료일보다 늦을 수 없습니다.           |  (오류 시에만 노출)
|                                                    |
|              [ 등록 ]        [ 취소 ]              |
+--------------------------------------------------+
```

**주요 인터랙션 요소**
- 제목/메모 입력 필드(메모는 여러 줄 입력 가능, 텍스트 세로 중앙 정렬)
- 카테고리 드롭다운: 미선택 시 '기본' 자동 지정 → 도메인 6장 규칙4, 시나리오 6 Main Flow 4
- 시작일/종료일 캘린더 선택 필드 → PRD REQ-04, 시나리오 6 Main Flow 1
- [등록] 버튼(취소 버튼보다 앞): startDate ≤ endDate 검증 실패 시 인라인 오류 → 시나리오 6 Alt Flow 3a, 도메인 6장 규칙6
- [취소] 버튼: 목록으로 복귀(저장 안 함)
- (비고) 같은 기간에 기존 Todo가 있어도 등록 제한 없음 → 도메인 6장 규칙7
- (비고) 미인증 상태로 접근 시 401 → 로그인 화면으로 리다이렉트(도메인 8장)

**반응형**: 데스크톱은 모달 오버레이, 모바일은 전체화면 페이지로 전환.

**모바일(<768px) 레이아웃 예시 (전체화면 폼)**
```
+----------------------------+
| ✕  Todo 등록                |
+----------------------------+
| 제목                        |
| [______________________]  |
| 카테고리                    |
| [ 기본 ▾ ]                  |
| 시작일                      |
| [ 2026-08-26  📅 ]         |
| 종료일                      |
| [ 2026-08-30  📅 ]         |
| 메모                        |
| [______________________]  |
| [______________________]  |
|                            |
| [        등록        ]    |
| [        취소        ]    |
+----------------------------+
```

## 5. Todo 편집 화면

**목적/진입 경로**: Todo 목록 화면의 특정 항목 [편집] 버튼 클릭 시 진입(본인 소유 Todo만 접근 가능).

```
+--------------------------------------------------+
|  Todo 편집                                   [X] |
+--------------------------------------------------+
|  제목      [_______________________________]     |
|  카테고리  [업무 ▾]                               |
|  시작일    [ 2026-09-01  📅 ]                     |
|  종료일    [ 2026-09-05  📅 ]                     |
|  메모      [_______________________________]     |
|  완료 여부 [ ] 완료로 표시                          |
|                                                    |
|              [ 저장 ]        [ 취소 ]              |
+--------------------------------------------------+
```

**주요 인터랙션 요소**
- 기존 값이 프리필된 제목/카테고리/기간/메모 필드: 시나리오 8 Main Flow 1
- 완료 여부 체크박스: 완료 토글과 동일 효과(상태 재계산) → 시나리오 10
- [저장] 버튼(취소 버튼보다 앞): 소유권 검증(403) 및 startDate ≤ endDate 재검증 → 시나리오 8 Alt Flow 2a/3a, 도메인 6장 규칙2·6
- [삭제] 버튼: 편집 화면이 아닌 Todo 목록 화면의 각 행에 위치(FE-10 구현 반영) → 시나리오 9
- [취소] 버튼: 변경 취소 후 목록 복귀
- (비고) 미인증 상태로 접근 시 401 → 로그인 화면으로 리다이렉트(도메인 8장)

**반응형**: Todo 등록 화면과 동일 패턴(모달 ↔ 전체화면 전환).

## 6. 회원정보 수정 화면

**목적/진입 경로**: 상단 네비게이션 "회원정보수정" 메뉴 클릭 시 진입(로그인 필수).

```
+--------------------------------------------------+
| my-ToDoList   [Todo목록] [회원정보수정] [로그아웃]  |
+--------------------------------------------------+
|              [ 회원정보 수정 ]                     |
|  이메일(id) [ user@example.com ]  (수정 불가, 표시용)|
|  이름       [_______________________]             |
|  비밀번호   [_______________________] (변경 시만 입력)|
|                                                    |
|              [   저장   ]                          |
+--------------------------------------------------+
```

**주요 인터랙션 요소**
- 이메일 필드: 읽기 전용 표시(식별자, 도메인상 id 변경 시나리오 없음)
- 이름 등 수정 가능 필드: 시나리오 5 Main Flow 1
- [저장] 버튼: 본인 여부 검증 후 갱신 → 시나리오 5 Main Flow 2·3, 도메인 6장 규칙2(소유권 검증)

**반응형**: 단일 카드 중앙 정렬, 데스크톱/모바일 구조 동일(폭만 축소).

## 7. 관리자 - 회원 목록 화면

**목적/진입 경로**: 상단 네비게이션(Admin 계정에만 노출)의 "회원관리" 메뉴 클릭 시 진입.

```
+--------------------------------------------------------------+
| my-ToDoList  [Todo목록][회원정보수정][회원관리][카테고리관리][로그아웃]|
+--------------------------------------------------------------+
|  회원 목록                                                     |
+--------------------------------------------------------------+
| 이메일                  이름     역할       가입일             |
| user1@example.com      홍길동   Member     2026-08-01         |
| admin@example.com       관리자   Admin      2026-07-01         |
| ...                                                            |
+--------------------------------------------------------------+
```

**주요 인터랙션 요소**
- 전체 회원 목록 테이블(id/email/name/role/createdAt): Admin 시나리오 1 Main Flow 3, 도메인 6장 규칙9
- 수정/삭제 액션 없음(범위 밖, 조회 전용) → Admin 시나리오 1 Postcondition
- (비고) Member 계정이 URL 직접 접근 시 403 → Admin 시나리오 1 Alt Flow
- (비고) 미인증 상태로 접근 시 401 → 로그인 화면으로 리다이렉트(도메인 8장)

**반응형**
- 데스크톱: 표 형태 그대로
- 모바일: 회원별 카드 스택(이메일/이름/역할/가입일 세로 나열)

## 8. 관리자 - 카테고리 관리 화면

**목적/진입 경로**: 상단 네비게이션(Admin 전용)의 "카테고리관리" 메뉴 클릭 시 진입.

```
+--------------------------------------------------------------+
| my-ToDoList  [Todo목록][회원정보수정][회원관리][카테고리관리][로그아웃]|
+--------------------------------------------------------------+
|  카테고리 관리                                                  |
+--------------------------------------------------------------+
|  신규 카테고리 이름 [_______________]   [ 추가 ]                |
+--------------------------------------------------------------+
| 이름       기본여부   생성일         액션                       |
| 기본       (기본)     2026-07-01     -                         |
| 업무       -          2026-07-05     [수정] [삭제]              |
| 개인       -          2026-07-05     [수정] [삭제]              |
+--------------------------------------------------------------+
|  [!] 삭제 시 해당 카테고리를 사용 중인 Todo는 '기본'으로          |
|      자동 재할당됩니다.                                        |
+--------------------------------------------------------------+
```

**주요 인터랙션 요소**
- 신규 카테고리 이름 입력 + [추가] 버튼: Admin 시나리오 2 등록 흐름, 도메인 6장 규칙3
- 목록의 [수정] 버튼: 인라인 이름 편집 → Admin 시나리오 2 수정 흐름(변경 시 참조 중인 모든 Todo에 즉시 반영)
- 목록의 [삭제] 버튼: 참조 중인 Todo가 있으면 자동으로 '기본' 카테고리로 재할당 후 삭제 → Admin 시나리오 3, 도메인 8장
- '기본' 카테고리 행: 삭제/수정 액션 비활성화(정책 미확정, 범위 밖) → Admin 시나리오 3 Precondition, PRD 3.2
- (비고) Member 계정이 API 직접 호출 시 403 → Admin 시나리오 2·3 Alt Flow
- (비고) 미인증 상태로 접근 시 401 → 로그인 화면으로 리다이렉트(도메인 8장)

**반응형**
- 데스크톱: 표 형태 그대로
- 모바일: 카테고리별 카드 스택, [수정]/[삭제] 버튼은 카드 하단에 배치

**모바일(<768px) 레이아웃 예시**
```
+----------------------------+
| ☰ my-ToDoList              |
+----------------------------+
| 카테고리 관리                |
| [__________]  [ 추가 ]     |
+----------------------------+
| 기본 (기본카테고리)          |
|   -                        |
+----------------------------+
| 업무                        |
|   생성일 2026-07-05         |
|   [수정]        [삭제]     |
+----------------------------+
| 개인                        |
|   생성일 2026-07-05         |
|   [수정]        [삭제]     |
+----------------------------+
```
